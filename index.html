Design philosophy

A cinematic interface, built from scratch

Deep black and navy backgrounds, electric blue and cyan holographic effects, an animated circular AI core, glowing interface elements, real-time voice visualisation, futuristic status panels and smooth animation — rendered entirely with CSS and a single Canvas, at 60 fps on a phone.

  • Animated arc reactor with scanner sweep, particles and waveform reactivity
  • Live telemetry: mode, model, latency, turns, memory, battery, frame rate
  • Mobile-first layout with a desktop mission-control grid
  • Four accent palettes, reduced-motion support and full keyboard control
  • Offline-capable app shell — install once, open anywhere

Technology stack

Zero dependencies in the app. Nothing to install to run it.

The interface is plain HTML5, CSS3 and ES modules, so the same code runs in a browser, as an installed PWA and inside an Android WebView via Capacitor. The optional Node proxy is the only server-side piece, and only if you deploy it.

Application

  • HTML5 — semantic, accessible structure
  • CSS3 — HUD styling, animation, responsive grid
  • JavaScript ES modules — 12 modules, no build step
  • Canvas 2D — the animated AI core
  • Service worker — offline shell + PWA
  • Web Storage — memory, notes, tasks, transcript

Intelligence

  • OpenAI, Groq, OpenRouter — OpenAI-compatible wire protocol
  • Google Gemini — generateContent streaming
  • Anthropic Claude — messages streaming
  • Custom proxy — your own OpenAI-compatible endpoint
  • Local Core — offline rule/tool engine, always available
  • Search — Wikipedia, Tavily, Brave, Serper

Delivery

  • GitHub Pages — this website and the web app
  • GitHub Actions — tests, build verification, APK builds
  • Capacitor — Android packaging
  • Node.js — optional key-hiding proxy in server/
  • PWA — installable on Android and desktop
  • Releases — signed-by-CI debug APK download

Android

3 · Install the APK

Every push to main builds an Android APK in GitHub Actions and attaches it to a release.

Download latest APK → 
adb install jarvis-ai.apk
# or build it yourself
git clone https://github.com/itzRuthik/Jarvis-ai.git
cd Jarvis-ai/android && ./gradlew assembleDebug

Run from source

git clone https://github.com/itzRuthik/Jarvis-ai.git
cd Jarvis-ai
node tools/serve.mjs        # http://localhost:5173
open http://localhost:5173/app/

Optional: hide the API key on a server

cd server
npm install
cp .env.example .env        # add your key
npm start                   # http://localhost:8787
# then in the app: Setup → Custom → base URL
# http://localhost:8787/v1

Environment & security

Your keys never touch this repository

JARVIS is built around a bring-your-own-key model. That has real consequences, and the project documents them instead of hiding them.

  • Never committed — keys live in browser storage on your device, or in server/.env which is git-ignored
  • Never bundled — the front end ships with no credentials of any kind
  • Server proxy option — the recommended setup for public deployments, with CORS allowlisting, rate limiting and Google Safe Browsing pre-checks
  • Session-only mode — keep the key in memory so it disappears when you close the tab
  • Data control — export a full backup, clear the transcript, or wipe everything with one button
  • Input validation — no eval, no unsanitised HTML, a strict Content-Security-Policy

Understand this before you paste a key: a direct browser → provider call exposes that key to anyone using the browser profile. Use a disposable key with a low spend limit, or run the proxy. 

# .env.example  (never commit .env)
PORT=8787
AI_PROVIDER=openai        # or gemini / anthropic
OPENAI_API_KEY=sk-...     # server-side only
OPENAI_MODEL=gpt-4o-mini
ALLOWED_ORIGINS=https://itzruthik.github.io
RATE_LIMIT_PER_MIN=30
GOOGLE_SAFETY_KEY=        # optional
PROXY_TOKEN=              # optional shared secret
# The browser only ever talks to this server.
